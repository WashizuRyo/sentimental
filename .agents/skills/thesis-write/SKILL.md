# Thesis Write

指定された論文範囲を執筆し、`citation-reviewer`と`consistency-reviewer`による独立レビューが収束するまで修正する。

## 入力を確定する

1. ユーザーの依頼から対象ファイル、章または節、執筆要件を特定する。
2. 対象が一意に定まらなければ推測せず、対象ファイルと章または節の指定を求める。
3. ユーザーがレビュー回数の上限を指定した場合は従う。指定がなければ最大5ラウンドとする。

## 執筆する

1. ルートの`AGENTS.md`と対象ファイルを確認し、指定範囲と前後の文脈を特定する。
2. `$thesis-writer` Skillを使い、指定された章または節を要件に従って執筆または改稿する。
3. ユーザーが「案だけ」と指定しない限り、対象のMarkdownファイルを直接編集する。
4. 編集差分を確認し、指定範囲外へ不要な変更を加えていないことを確かめる。

## 並列レビューを実行する

各レビューラウンドで次を行う。

1. `citation-reviewer`と`consistency-reviewer`のCustom Agentを1つずつ、同じラウンド内で並列に起動する。
2. 両者へ次の情報を渡す。
   - ユーザーが指定した対象と執筆要件
   - 対象ファイルと今回変更した範囲
   - 最新の本文をレビューすること
   - 本文を編集せず、指摘だけを返すこと
3. 両方のSubagentが完了するまで待つ。
4. 2つのレビュー結果を統合し、重複する指摘をまとめる。

## 指摘を修正する

1. 「重大」「要修正」「軽微」の指摘と、リポジトリ内の既存資料だけで解決できる「要確認」を対応可能な指摘とする。
2. 対応可能な指摘がなければ、レビューが収束したものとして終了する。
3. 対応可能な指摘があれば、`$thesis-writer` Skillを使ってすべて修正する。
4. レビュアーの修正文を機械的に貼り付けず、研究設定、原資料、前後の文脈を確認し、妥当な修正だけを反映する。
5. 修正後に差分を確認し、新しい`citation-reviewer`と`consistency-reviewer`を並列に起動して再レビューする。
6. 初回レビューを1ラウンド目として数え、対応可能な指摘がなくなるまで反復する。

## 安全に終了する

- 新しい文献、実験結果、ユーザー判断などがなければ解決できない「要確認」を、推測や架空の情報で埋めない。未解決事項として示し、ユーザー入力待ちで終了する。
- 同じ実質的な指摘が2ラウンド連続で残り、追加修正で改善できない場合は、対立する要件または不足情報を示して終了する。
- 修正を指示しても対象ファイルの差分が生じない場合は理由を確認し、解決できなければ終了する。
- 最大レビュー回数に達しても指摘が残る場合は、残存する指摘と推奨対応を示して終了する。
- ユーザーが指定していない別章を勝手に編集しない。指定範囲側で解消できなければ残存事項として報告する。
- レビュー結果を受け取っただけで完了とせず、いずれかの終了条件を満たすまで修正と再レビューを継続する。

## 完了を報告する

- 執筆または改稿したファイルと章・節を示す。
- 実行したレビューラウンド数を示す。
- 各ラウンドで反映した主要な修正をまとめる。
- 2つのレビュアーが対応可能な指摘なしと判断したかを示す。
- 資料不足、ユーザー判断待ち、対象範囲外などで残った事項を示す。
